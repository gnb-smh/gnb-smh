## Next acceptance bottlenecks

The immediate package gate is **trustworthy signer input and fee verification across the intended PQ-PSBT paths**. Existing JSON policy signing is not evidence of the requested six roles, node-verified inputs, fee ceiling or offline multisig workflow. Until the pinned implementation, independent vectors, regressions and actual CLI/RPC/WASM paths are reviewed, the wallet-tools front remains unproved.

The largest structural technology gap directly evidenced by the inspected specification is **mergeset ledger application**: the DAG currently chooses a selected chain without applying off-chain mergeset transactions or paying those rewards. The next design gate for that front is a single deterministic specification of transaction ordering/conflicts, rewards, undo/reorg and activation, checked by an independent executable reference and producer boundary tests. No throughput gain can be credited before implementation and measurement. This is an assessment of required evidence, not authorization to retry previously blocked reproduction tasks.

Other required gates remain: a reproducible 100,000-block IBD baseline and resource methodology; executable definitions for any new policy/finality rule; formal safety/liveness evidence where requested; full round 3 node and **separate** crypto tests; actual functional outcomes with failures/skips preserved; applicable WASM rebuild and pin verification; exact-head CI; and the missing seven technology weights plus a pinned, equally assessed comparator/rubric before any score. The prompt's external consensus audit, adversarial testnet campaign and bug-bounty prerequisites for mainnet activation remain unmet by these package checks. No activation height or rollout readiness is inferred here.
